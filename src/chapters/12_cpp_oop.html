C++ & Object-Oriented Programming

C++ Introduction

  • High-level, general-purpose language; designed by Bjarne Stroustrup at Bell Laboratories; started 1979, named C++ in 1983, first commercial release 1985.
  • Earlier called "C with Classes". Supports procedural + object-oriented (multi-paradigm) — called a partial / semi object-oriented language (because main() and global functions exist outside classes).
  • Compiled language; case-sensitive; files saved with extension .cpp.
  • Used in: video games, embedded systems, IoT devices, operating systems, browsers, databases.
  • Compilers/IDEs: Turbo C++, Code::Blocks, Dev-C++, Borland C++, Microsoft Visual C++, GCC/G++ (GNU Compiler Collection), Clang.
  • IDE (Integrated Development Environment) = source-code editor + build automation tools + debugger + compiler/interpreter.
#include <iostream>      // header file (library)
using namespace std;     // namespace std
int main() {             // execution starts here
    cout << "Hello World"; // display output
    return 0;            // return to OS
}
// single-line comment     /* multi-line comment */
  • iostream — basic input/output services. Namespace — avoids name collisions.
  • cin — object of input stream (istream), used with >> (extraction). cout — object of output stream (ostream), used with << (insertion).
  • main() — starting point; controls execution; return value used by runtime.

Data Types, Modifiers & Storage Classes

  • Data types: int, float, double, char, bool, void, wchar_t.
  • Modifiers: short (range less, 2 bytes), long (range more, 4/8 bytes), unsigned (only positive), signed (both).
  • Storage classes (5): auto (default for locals), register (stored in CPU register), static (initialised once, keeps value till end of program), extern (visible to all files), mutable (member of a const object can be changed).
  • C++ has 95 keywords (C++20; older references: 63 or 84). C has 32 keywords (C89).
  • Keywords are reserved words with predefined meaning; can't be used as identifiers/variable names (gives syntax/compile error).

Operators

  • Arithmetic, relational, logical, bitwise (& | ^ ~ << >>), assignment, misc.
  • Misc operators: sizeof, conditional (?:, ternary), comma, dot (.) and arrow (->), casting, address-of (&), pointer/dereference (*), scope resolution (::), new/delete.
  • & returns the memory address of a variable; * is the dereference operator; new = dynamic memory allocation.
  • Empty string = string with zero characters (""). Sequence of characters in double quotes = string literal.

Control Structures

  • for loop — entry-controlled; used when number of iterations is known.
  • while loop — entry-controlled; used when iterations are not known in advance.
  • do-while — exit-controlled; body executes at least once.
  • Loop control: break (exit loop), continue (skip current iteration), goto (jump to a label).

Structure & Class

  • Structure (struct) — collection of variables of different types under one name; members public by default.
  • Class (class) — building block of OOP; members private by default.
  • Access specifiers: public (accessible everywhere), private (only within class), protected (class + derived classes).
class Student {
  private:
    int roll;
  public:
    Student(int r) { roll = r; }        // constructor
    void show() { cout << roll; }
    ~Student() { }                      // destructor
};

Functions in C++

  • Types: standard library (predefined) and user-defined.
  • Function overloading — same name, different parameters (compile-time polymorphism): int test(); int test(int a); float test(double a);
  • Inline function — inline keyword; compiler copies function code at the call location, making execution faster for small functions.
  • Recursion — function calling itself.
  • Friend function, virtual function (runtime polymorphism), constructor (same name as class, no return type), destructor (~).

Exception Handling

  • Handles run-time errors. Keywords: try (code to test), throw (raise exception when problem detected), catch (handle it). Java/Python add finally (always executes).
try {
    if (b == 0) throw "Divide by zero";
    cout << a / b;
} catch (const char* msg) { cout << msg; }

Types of Errors

  1. Syntax / compile-time errors — violating language grammar (missing ;, brackets); detected by compiler.
  2. Logical / semantic errors — program runs but gives wrong output due to wrong logic.
  3. Runtime errors / exceptions — occur during execution (divide by zero, invalid memory access, file not found).
  4. Interface errors — mismatch between software and APIs/hardware interface.
  5. Linker errors — e.g. undefined reference / missing main().

Translators

  • Assembler — assembly code → machine code.
  • Compiler — whole high-level program → machine/object code at once; faster execution; shows all errors after compilation (C, C++). Source code → object code.
  • Interpreter — translates and executes line by line; slower; stops at first error (Python, BASIC). First interpreter ~1952.
  • Linker joins object files; loader loads program into memory.

Algorithm & Flowchart

  • Algorithm — step-by-step procedure; from al-Khwarizmi (Persian, 9th century).
  • First computer algorithm: Note G by Ada Lovelace (1843) to calculate Bernoulli numbers on Babbage's Analytical Engine — she is the first computer programmer.
  • Flowchart — by Frank & Lillian Gilbreth (1921, "flow process chart", presented to ASME). Herman Goldstine & John von Neumann used flowcharts for programs (1947).
  • Types: macro (major steps), mini, micro (detailed) flowcharts.

OOP Concepts

  • OOP binds data and functions together into objects — simple, reusable pieces of code. Concept by Alan Kay (1960s, coined the term).
  • First OOP language: Simula (1967, Ole-Johan Dahl & Kristen Nygaard). First pure OOP language: Smalltalk (1972).
  • OOP languages: Java, Python, C++, C#, JavaScript, PHP, Go (partly), Ruby, Visual Basic .NET, Swift, Kotlin, Smalltalk.
  • Semi-OOP: C++. Often called 100% OOP: Java (but primitives exist — Smalltalk is truly pure).
  • Benefits: reusability, less redundancy, easy maintenance, security, design benefits, productivity, easy troubleshooting, flexibility, problem solving.

Pillars of OOP

  • Class — blueprint / group of similar objects.
  • Object — instance of a class with state (attributes) and behaviour (methods); a physical entity (car, pen, chair).
  • Encapsulation — wrapping data and methods into one unit (data hiding).
  • Abstraction — showing only essential information, hiding details.
  • Inheritance — one class inherits attributes and methods of another. Types: single, multiple, multilevel, hierarchical, hybrid.
  • Polymorphism — "many forms": compile-time (overloading) and run-time (overriding/virtual functions).
  • Data hiding — protecting data from unauthorised access outside the class.
