Theory of Computation (TOC)

Introduction

  • Branch of theoretical computer science that studies how problems can be solved using algorithms / abstract machines.
  • 3 theories: Computability theory (what can and can't be computed), Complexity theory (what makes problems computationally hard or easy), Automata theory (abstract machines and the problems they solve).
  • Concepts: finite automata, regular expressions, context-free grammars, Turing machines, decidability, halting problem, pumping lemma.
  • Applications: cryptography, algorithm analysis, quantum computation, logic, compiler design, string/pattern matching, AI.
  • Alan Turing — father of theoretical computer science & AI; invented the Turing machine (1936). His teacher Alonzo Church developed lambda calculus (λ-calculus).
  • Church–Turing thesis: anything that can be computed by a step-by-step procedure can be computed by a Turing machine.

Automata Basics

  • Automaton = abstract machine. Symbol = character. Alphabet (Σ) = finite set of symbols. String/word = finite sequence of symbols. Language = set of strings.
  • Machines (weakest → strongest): Finite Automata → Pushdown Automata → Linear Bounded Automata → Turing Machine.

Chomsky Hierarchy

By linguist Noam Chomsky (1956) — classifies grammars/languages into 4 types.

Finite Automata (DFA & NFA)

  • Concept by Warren McCulloch & Walter Pitts (1943, neurophysiologists studying the brain). Recognises regular languages (Type 3) — e.g. phone numbers, patterns. Used in text processing, compilers (lexical analysis), network protocols.
  • Formally a 5-tuple (Q, Σ, δ, q0, F).

DFA and NFA have equal power. A machine without output = acceptor.

Moore & Mealy Machines

  • Finite automata with output (transducers); 6-tuples (Q, Σ, Δ, δ, λ, q0) — no final states.
  • Moore machine — output depends only on the present state.
  • Mealy machine — output depends on the present state and current input. Generally needs fewer states.

Pushdown Automata (PDA)

  • Finite automaton + stack (extra memory, LIFO). Recognises context-free languages (Type 2), e.g. aⁿbⁿ, balanced brackets. Used in parsers.
  • Components: input tape, finite control, stack (push/pop).
  • DPDA is less powerful than NPDA.

Linear Bounded Automata (LBA)

  • Turing machine with tape limited to the input size (between left and right end markers). Recognises context-sensitive languages (Type 1).
  • Introduced by John Myhill (1960); Peter Landweber and S.-Y. Kuroda showed equivalence with CSL.
  • More powerful than PDA, less powerful than TM.

Turing Machine

  • Invented by Alan Turing in 1936 — mathematical model of a general-purpose computer; most powerful model; accepts recursively enumerable languages (Type 0).
  • Has an infinite tape divided into cells, a read/write head moving left/right, finite control (states). Reads one symbol at a time; can modify its own input ("writing machine").
  • 7-tuple (Q, Σ, Γ, δ, q0, B, F). Accept state = successful; reject state = unsuccessful.
  • Halting problem — whether a TM will halt on an input or run forever — is undecidable (proved by Turing).
  • Variations (all equal in power): multi-track, two-way infinite tape, multi-tape, multi-head, multi-dimensional, non-deterministic TM, universal TM.

Regular Expressions & Closure Properties

  • Kleene star (Σ*) — zero or more repetitions; includes null (ε). E.g. meow* → meo, meow, meoww…
  • Kleene plus (Σ⁺) — one or more repetitions; excludes null.
  • Closure property: applying an operation to languages of a class yields a language of the same class.

Myhill–Nerode Theorem & Pumping Lemma

  • Myhill–Nerode theorem (1958): necessary and sufficient condition for a language to be regular; used to prove regularity and to minimise DFA states.
  • Pumping lemma: "pumping" = generating many strings by repeating a part; "lemma" = intermediate theorem. Two versions — for regular languages and for context-free languages. Used to prove a language is not regular / not context-free (e.g. aⁿbⁿ is not regular).

Compiler Phases (TOC application)

  1. Lexical analysis (scanner — tokens; uses finite automata)
  2. Syntax analysis (parser — parse tree; uses CFG/PDA)
  3. Semantic analysis (type checking)
  4. Intermediate code generation (e.g. three-address code)
  5. Code optimization
  6. Code generation (target machine code)

Symbol table and error handler work with all phases. Front end = phases 1–4; back end = 5–6.

Cloud Computing

Basics

  • Storing and accessing data and programs on remote servers over the Internet instead of your own computer.
  • Concept credited to J. C. R. Licklider (American computer scientist, 1960s, "Intergalactic Computer Network"). Term popularised ~1996–2006 (Amazon EC2, 2006).
  • Primary use: data storage. Characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity, measured (pay-as-you-go) service. Cloud services have a one-to-many relationship with users.

Architecture

  1. Front end — client side: thick (fat) client (powerful computer running a full OS; most logic local, e.g. MS Outlook, Word) and thin client (lightweight device relying on server, e.g. Gmail, Office 365 web, online games, search engines).
  2. Back-end platform — servers, storage; core of cloud; also called cloud engine / SAN storage.
  3. Cloud-based delivery & network — Internet, intranet, intercloud.

Deployment Models

  • Public cloud — shared resources, anyone can use (AWS, Azure, Google Cloud).
  • Private cloud — dedicated to one organization (IBM, Dell, VMware, Oracle, Cisco).
  • Hybrid cloud — public + private (Netflix, Hulu, Uber, Airbnb rely on hybrid/multi-cloud).
  • Community cloud — shared by organizations with common concerns.

Key Terms

  • Virtualization — creating virtual versions of servers, storage, networks, OS; backbone of cloud computing. Hypervisor (VMM): Type 1 bare-metal (VMware ESXi, Hyper-V), Type 2 hosted (VirtualBox).
  • Cloud migration — moving apps, data and IT resources to the cloud.
  • Cloud bursting — app runs in private cloud and "bursts" to public cloud during demand spikes. (Notes describe it as failure due to a spike in demand.)
  • Cloud Cube Model — by the Jericho Forum; for cloud security; 4 dimensions: internal/external, proprietary/open, perimeterised/de-perimeterised, insourced/outsourced.
  • Phases of cloud computing (3): strategy, planning, deployment.
  • Hadoop — open-source framework (Apache) to store and process big data across a cluster of computers (HDFS + MapReduce); key for big-data analytics.
  • AWS Well-Architected — 6 pillars: operational excellence, security, reliability, performance efficiency, cost optimization, sustainability.
  • Rackspace — cloud service provider company.

Cyber Security

Computer Virus

  • VIRUS = Vital Information Resources Under Siege. A program that copies itself and infects a computer without the owner's permission.
  • First computer virus: Creeper (Bob Thomas, 1971). First PC (boot-sector) virus: Brain (1986, Basit & Amjad Farooq Alvi, Pakistan). First virus for microcomputers: Elk Cloner (1982).
  • ILOVEYOU (Love Bug) — 2000; spread through e-mail; Onel de Guzman (Philippines).
  • Code Red — worm, July 2001; attacked Microsoft IIS web servers.
  • Pattern used to identify a virus = virus signature.

Antivirus software

Avira, McAfee, AVG, Quick Heal (India), Kaspersky, Avast, Panda, Norton (Symantec), Bitdefender, Windows Defender.

Cyber Attacks & Frauds

  • Phishing — fraudulent e-mails/links/websites to steal sensitive info (passwords, card numbers).
  • Smishing — SMS phishing. Vishing — voice phishing via calls / VoIP.
  • Pharming — malicious code redirects users from a legitimate site to a fake one (DNS poisoning) — "phishing + farming".
  • Spoofing — faking identity: IP, DNS, e-mail, caller ID, website.
  • Sniffing — capturing network packets (tapping).
  • Spooling — Simultaneous Peripheral Operations On-Line (e.g. print queue) — not an attack, but often asked alongside.
  • Spam — unsolicited bulk e-mail (junk).
  • Hacker — person who gains illegal access to a system (black hat); ethical hacker = white hat; grey hat in between.
  • Skimming — device copies the magnetic stripe of a credit/debit card at ATM, petrol pump or point of sale.
  • DoS / DDoS — flooding a server to make it unavailable.
  • Man-in-the-middle, SQL injection, cross-site scripting (XSS), brute force, zero-day attacks.
  • Social engineering — manipulating people into revealing information.

Cyber Security Tools & Practices

  • Firewalls, antivirus, anti-malware, encryption tools, VPN, strong passwords, two-factor authentication (2FA), intrusion detection systems (IDS), regular updates/patches, backups.
  • CIA triad: Confidentiality, Integrity, Availability.
  • Encryption: symmetric (same key — AES, DES) and asymmetric (public/private keys — RSA). Digital signature ensures authenticity & non-repudiation.
