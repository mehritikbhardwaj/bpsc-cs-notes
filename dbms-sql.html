Basic Concepts of Database

Hierarchy: Bit → Byte → Field → Record → Table/File → Database

  • Bit = smallest unit (0/1). Byte/character = 8 bits. Field = group of bytes. Record = group of fields. File/Table = group of records. Database = group of files/tables.
  • Database: organised collection of data that can be easily accessed, updated and managed.
  • DBMS (Database Management System): software that stores, modifies and retrieves data. RDBMS: DBMS that stores data in related tables.
  • First DBMS: IDS (Integrated Data Store) by Charles Bachman (1960s).
  • Father of relational database: E. F. Codd (IBM), relational model paper in June 1970.
  • Metadata: data about data (stored in the data dictionary).
  • Most popular open-source DBMS: MySQL. First graphical query language: QBE (Query By Example), developed by Moshe Zloof (IBM).

Characteristics of DBMS

Less data redundancy & inconsistency, data integrity & security, stores any type of data, ACID properties, easy access, SQL support, data sharing, decision making, backup & recovery, multi-user concurrent access.

Examples

MySQL, MS SQL Server, SQLite, PostgreSQL, Oracle, MS Access, IBM DB2, MariaDB, Sybase, FoxProMongoDB (document), Cassandra (column), Redis (key-value), Neo4j (graph), CouchDB, Couchbase, HBase, Amazon DynamoDB, Firebase, Google Bigtable, Elasticsearch

Before databases, data was kept in separate files (file system). Its limitations led to DBMS.

Components of DBMS & Users

  • Hardware — hard disk, monitor etc. Software — DBMS itself, gives interface. Data — collection of information. Procedures — rules/instructions. Database languages — DDL, DML, DCL. Data manager — manages operations.
  • DBA (Database Administrator) — maintains, secures and operates databases; ensures data is stored and retrieved correctly; designs and implements new features with developers; manages backup, recovery, access control.
  • Other users: application programmers, end users (naive, sophisticated), database designers.

Database Architecture (Tiers)

  1. 1-tier (single tier) — database directly available to the user on the same machine (local database system); any change is done directly on the database. Used for local application development.
  2. 2-tier — client–server. Client application talks to the server using APIs like ODBC (Open Database Connectivity, by Microsoft, SQL-based) and JDBC (Java Database Connectivity, by Sun Microsystems).
  3. 3-tier — client (presentation) ↔ application server (business logic) ↔ database server. Used for large web applications.

Three-Schema Architecture (ANSI/SPARC)

  • Proposed by ANSI/SPARC (American National Standards Institute / Standards Planning and Requirements Committee).
  • External level (view level) — closest to the user; shows only relevant data; many views for different users.
  • Conceptual level (logical level) — describes structure of the whole database: entities, relationships, constraints, security. Designed by DBA/programmers. Doesn't care how data is stored.
  • Internal level (physical level) — lowest level; how data is actually stored on disk (files, blocks, indexes, compression, encryption).
  • Data independence: logical (change conceptual schema without changing external) and physical (change internal without changing conceptual).

Schema vs Instance

  • Schema: logical design / blueprint / skeleton of the database (table names, fields, data types, relationships). Defined using DDL; rarely changes. Types: physical schema (storage in files & indices), logical schema (tables, views, integrity constraints — ER model used here), view schema (how end users interact).
  • Instance: snapshot of the data in the database at a given moment; changes with insert/update/delete.

ACID Properties (Transactions)

  • Atomicity — all or nothing: a transaction either completes fully or not at all.
  • Consistency — database moves from one consistent state to another (before = after in terms of rules, e.g. total balance).
  • Isolation — concurrent transactions don't interfere; each behaves as if alone.
  • Durability — once committed, changes are permanently saved even after system failure.

Transaction states

Active → Partially committed → Committed; or Active → Failed → Aborted (rollback). Concurrency problems: dirty read, lost update, unrepeatable read, phantom read. Solutions: locking (shared/exclusive, 2-Phase Locking), timestamp ordering.

  • 3 components: Entity, Relationship, Attribute.

Entity

  • A definable thing (person, object, concept, event) about which data is stored.
  • Strong entity — not dependent on any other entity; has a primary key.
  • Weak entity — depends on another (owner) entity for existence; has only a partial key (discriminator).

Types of attributes

  1. Key attribute — uniquely identifies the entity (e.g. Roll no.); underlined.
  2. Composite — made of other attributes (Address = street + city + state + pin).
  3. Single-valued — only one value (DOB, gender).
  4. Multivalued — more than one value (phone numbers, e-mail IDs).
  5. Derived — computed from another (Age from DOB) — dashed oval.
  6. Stored — fixed value from which others are derived (DOB).

Relationship & Cardinality

  • Relationship describes association among entities (diamond).
  • Cardinality ratios: one-to-one, one-to-many, many-to-one, many-to-many. E.g. one student enrolled in exactly one course = one-to-one.
  • High cardinality = many distinct values in a column; low cardinality = many repeated values.
  • Participation: total (double line — every entity must participate) or partial (single line).

Specialization, Generalization, Aggregation

  • Specialization — top-down: Person → Customer, Employee.
  • Generalization — bottom-up: combine common features into a higher entity.
  • Aggregation — a relationship is treated as an entity to make a more meaningful entity.

Database Keys

  1. Super key — set of one or more attributes that uniquely identifies rows (e.g. {Emp_id}, {Emp_id, Emp_name}).
  2. Candidate key — minimal super key; one of them becomes primary key.
  3. Primary key — chosen candidate key; unique, NOT NULL; only one per table.
  4. Alternate key — candidate keys not chosen as primary (also "secondary keys").
  5. Composite / compound key — key made of two or more attributes when no single attribute is unique (ATM card + PIN; username + OTP).
  6. Foreign key — column that refers to the primary key of another table; links tables; maintains referential integrity; can be NULL and duplicate.
  7. Surrogate key — system-generated synthetic key (auto-increment ID), used e.g. when merging data of two companies.

Normalization

Process of removing redundancy and unwanted anomalies by decomposing tables. Introduced by E. F. Codd.

Anomalies (why normalize)

  • Insertion anomaly — can't insert data without other data (e.g. can't add a new branch until a student joins it).
  • Deletion anomaly — deleting a row loses other useful data (deleting the last student of a branch deletes branch info).
  • Update anomaly — same data stored in many rows must be updated everywhere, else inconsistency.

Normal forms

NFCondition
1NFAll values atomic (no repeating groups / multivalued attributes)
2NF1NF + no partial dependency (every non-key attribute fully dependent on whole primary key)
3NF2NF + no transitive dependency (non-key → non-key)
BCNF (3.5NF)For every FD X → Y, X is a super key. Advanced version of 3NF (Boyce–Codd)
4NFBCNF + no multivalued dependency
5NF (PJNF)No join dependency (Project-Join Normal Form)
6NF / DKNFDomain-Key Normal Form — based on domains and keys

Advantages: reduced redundancy, better consistency, simpler maintenance, improved performance for updates. Disadvantages: time-consuming, more joins (slower reads), careless decomposition can be bad, increased complexity.

Codd's 12 Rules

13 rules (numbered 0–12) set out by E. F. Codd in 1985 that define a "true" relational DBMS.

  1. Foundation rule
  2. Information rule (all data in tables)
  3. Guaranteed access rule (table + primary key + column)
  4. Systematic treatment of NULL values
  5. Active/dynamic online catalog based on the relational model
  6. Comprehensive data sub-language rule
  7. View updating rule
  8. High-level insert, update and delete
  9. Physical data independence
  10. Logical data independence
  11. Integrity independence
  12. Distribution independence
  13. Non-subversion rule

SQL – History & Basics

  • SQL = Structured Query Language — standard language for accessing and manipulating relational databases. Old name: SEQUEL (Structured English Query Language).
  • Developed at IBM by Donald D. Chamberlin & Raymond F. Boyce (1974), based on Codd's relational model. IBM's prototype: System R.
  • First commercial SQL RDBMS: Oracle (Relational Software Inc., 1979).
  • ANSI standard in 1986, ISO in 1987. SQL Server is owned by Microsoft.
  • SQL is a 4th-generation language (4GL), declarative, not case-sensitive; statements end with semicolon.
  • Advantages: high speed, no coding needed, well-defined standards (ISO/ANSI), portable, interactive, multiple data views.

  • DROP — deletes whole table (structure + data). TRUNCATE — deletes all rows, keeps structure; faster; no WHERE; DDL. DELETE — deletes one or more rows with WHERE; DML; can be rolled back.

  • COMMIT = permanently save; ROLLBACK = undo; SAVEPOINT = creates a point to roll back to.

  roll INT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,

UPDATE student SET marks = 90 WHERE roll = 1;
DELETE FROM student WHERE roll = 1;
ALTER TABLE student ADD email VARCHAR(60);
SELECT name, marks FROM student WHERE city = 'Patna' ORDER BY marks DESC;
GRANT SELECT ON student TO teacher;
CREATE INDEX idx_name ON student(name);

Query Clause Order & Operators

Writing order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
Execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.

  • Comparison: = <> != > < >= <=. Equality uses a single =.
  • Logical: AND, OR, NOT. Others: BETWEEN, IN, LIKE (% any characters, _ one character), IS NULL.
  • DISTINCT removes duplicate rows from the result.
  • GROUP BY groups rows having same values; can be used without HAVING.
  • HAVING filters groups; used with GROUP BY; can contain aggregate functions. Added because WHERE cannot use aggregate functions.
SELECT gender, COUNT(*) FROM members GROUP BY gender HAVING COUNT(*) > 5;
SELECT lastname, age FROM customer WHERE country <> 'UK' ORDER BY lastname DESC;

Constraints

Rules applied to columns to limit the type of data that can go into a table (integrity constraints).

  • NOT NULL — value can't be null. UNIQUE — no duplicates. PRIMARY KEY — NOT NULL + UNIQUE. FOREIGN KEY — refers to a row in another table. CHECK — validates a condition. DEFAULT — default value if none given. CREATE INDEX — speeds up reads.
  • If a constraint is violated, the action is aborted.

Views, Cursors, Locks, Triggers

  • View — virtual table created by CREATE VIEW from one or more tables; stores no data itself.
  • Cursor — database object/pointer to process the result set row by row; a temporary work area in memory. Implicit and explicit cursors.
  • Locks — maintain integrity/consistency in transactions; solve concurrency problems. Levels: row, page, table, database. Problem: locks can delay transactions (and cause deadlock).
  • Trigger — procedural code automatically executed in response to an event (INSERT, UPDATE, DELETE) on a table. Types: row-level and statement-level; BEFORE / AFTER.
  • Pointers in database allow fast access to data.
  • Stored procedure — saved, precompiled set of SQL statements that can be called by name.

SQL Joins

Combine rows from two or more tables on a related column.

JoinReturns
INNER JOIN (default)Only matching rows from both tables
LEFT OUTER JOINAll rows of left table + matching rows of right (NULL where no match)
RIGHT OUTER JOINAll rows of right table + matching rows of left
FULL OUTER JOINAll rows from both tables
CROSS JOINCartesian product (rows A × rows B)
SELF JOINTable joined with itself
  • Inner join sub-types: Theta join (any condition: <, >, …), Equi join (uses =), Natural join (automatically on columns with the same name, no duplicate column).
SELECT s.name, c.title
FROM student s INNER JOIN course c ON s.course_id = c.id;

PostgreSQL, NoSQL, PL/SQL

  • PostgreSQL (Postgres) — free, open-source, object-relational DBMS; written in C; default DB of macOS Server; used by Uber, Netflix, Instagram, Spotify. SQL support added in 1996. Supports JSON, IPv4/IPv6/MAC data types. A named collection of tables = schema. Max identifier length 63 characters.
  • NoSQL — for unstructured/semi-structured data; easy schema evolution; horizontally scalable; distributed; mostly no full ACID (BASE model). Types: document, key-value, column-family, graph.
  • PL/SQL — Procedural Language extension to SQL by Oracle; block-structured; supports variables, data types, control structures, procedures, functions, triggers and packages.
  • RAID = Redundant Array of Independent (Inexpensive) Disks.
