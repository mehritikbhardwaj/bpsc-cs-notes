Classification of Computers

  • By data handled: Analog (continuous data — thermometer, speedometer), Digital (discrete 0/1), Hybrid (both — ICU machines).
  • By size/power: Supercomputer (fastest; measured in FLOPS; e.g. Frontier/El Capitan) > Mainframe (banks, many users) > Minicomputer > Microcomputer (PC, laptop, tablet, smartphone).
  • By purpose: general purpose and special purpose (embedded).

Input & Output Devices

  • Input: keyboard (QWERTY by Christopher Sholes), mouse (Douglas Engelbart, 1960s), scanner, joystick, light pen, touchscreen, microphone, webcam, barcode reader, MICR (Magnetic Ink Character Recognition — bank cheques), OCR, OMR (Optical Mark Reader — answer sheets), biometric sensor, trackball, graphics tablet.
  • Output: monitor (CRT, LCD, LED, OLED), printer, plotter (large drawings), speaker, projector, headphones.
  • Printers: impact (dot matrix, daisy wheel, line printer) and non-impact (inkjet, laser, thermal). Speed: CPS (characters/sec), LPM (lines/min), PPM (pages/min).
  • Both input & output: touchscreen, modem, network card, headset.
  • Monitor resolution in pixels; refresh rate in Hz. Keyboard function keys F1–F12.

Software

  • System software: operating system, device drivers, utilities (antivirus, disk cleanup), language translators (compiler, interpreter, assembler), firmware.
  • Application software: word processors (MS Word), spreadsheets (Excel), presentation (PowerPoint), DBMS, browsers, media players, games.
  • Licensing: proprietary (closed source), freeware (free, closed), shareware (trial), open source (source available — Linux, LibreOffice, Firefox), FOSS (Free and Open Source Software).
  • Hardware = physical parts; software = programs; firmware = software stored in ROM; liveware/humanware = users.

Ports & Buses

  • USB (Universal Serial Bus, 1996) — Type A, B, C; USB 2.0 (480 Mbps), 3.0 (5 Gbps), USB4 (40–80 Gbps).
  • HDMI (High-Definition Multimedia Interface), VGA (Video Graphics Array), DVI, DisplayPort, Thunderbolt, Ethernet (RJ-45), PS/2 (old mouse/keyboard), serial (COM) and parallel (LPT) ports.
  • Motherboard: CPU socket, RAM slots, chipset, PCIe slots, SATA ports, BIOS/UEFI chip, CMOS battery.

Data Deletion, Recovery & Security

  • Deleting a file usually removes only its entry/pointer; data stays on disk until overwritten. First it goes to the Recycle Bin (Windows) / Trash (macOS).
  • Soft delete — recoverable (Recycle Bin). Permanent delete (Shift + Delete) — bypasses Recycle Bin but data can still often be recovered by recovery software (Recuva, TestDisk) until overwritten.
  • Data recovery — retrieving deleted, lost or corrupted data from storage.
  • Security concern — sold/discarded devices can leak personal data. Safe methods: data shredding/wiping (overwrite several times), disk formatting with overwrite, physical destruction, full-disk encryption.
  • Formatting: quick format (only clears file table) vs full format (scans and overwrites).
  • Backups: full, incremental, differential; cloud backup.

Gray Code

  • Also called unit-distance code / reflected binary code — successive code words differ in only one bit.
  • Used in error correction, digital communication, rotary encoders, K-maps. Invented by Frank Gray (patented 1953).
  • Non-weighted code.

Boolean Algebra Basics

  • Used to analyse and simplify digital (logic) circuits; based on mathematical logic with only two values: true (1) and false (0).
  • Founded by George Boole in 1854 ("The Laws of Thought").
  • 1 = yes / on / high; 0 = no / off / low. Also used in set theory and statistics.
  • Three basic operations: AND (conjunction, ·), OR (disjunction, +), NOT (negation, ′ or ¯).
  • Reducing a Boolean expression reduces the number of logic gates needed.

Logic Gates

  • Basic gates: AND, OR, NOT. Universal gates: NAND, NOR (any circuit can be built from them alone). Exclusive gates: XOR, XNOR. Total common gates = 7.

  • NOT (inverter): single input, output = A′. The bubble on a gate symbol means inversion.
  • NAND = AND + NOT: Q = (A·B)′. NOR = OR + NOT: Q = (A+B)′; used in Apollo Guidance Computer.
  • XOR (exclusive OR, EX-OR): output 1 when inputs differ. Used in half/full adders, subtractors, parity, error detection, encryption.
  • XNOR (equivalence gate): output 1 when inputs are equal. Used in comparators, data multiplexing/synchronisation.

Truth table

Shows the relation between inputs and outputs. Number of rows = 2n (n = variables). 3 variables → 8 rows.

  • Duality theorem: swap AND ↔ OR and 0 ↔ 1 — the dual of a valid identity is also valid. E.g. dual of A + 0 = A is A · 1 = A.

SOP, POS, Minterms & Maxterms

  • SOP — Sum of Products (sum of minterms): e.g. AB + BC + AC. Uses the 1s of the truth table.
  • POS — Product of Sums (product of maxterms): e.g. (A + B)(A + C). Uses the 0s.
  • Minterm — AND term containing every variable; variable = 1 written as A, 0 as A′. Written Σm(…).
  • Maxterm — OR term containing every variable; variable = 0 written as A, 1 as A′. Written ΠM(…).
  • Canonical form — every term contains all variables, e.g. F = ABC + AB′C + A′BC (standard SOP).
Truth table F = 1 for rows 001, 010, 011, 101 → F = Σm(1, 2, 3, 5) = A′B′C + A′BC′ + A′BC + AB′C. The 0-rows give ΠM(0, 4, 6, 7).
F = A′B + AB′ + AB → Σm(1, 2, 3).
POS (A + B)(A + B′): maxterm 00 → 0 and 01 → 1 → ΠM(0, 1).

Karnaugh Map (K-Map)

  • Graphical method for simplifying Boolean expressions step by step. Proposed by Veitch (1952), modified by Maurice Karnaugh (Bell Labs, 1953) — also called Veitch diagram / K-map. A K-map is a 2-D truth table.
  • Cells = 2n: 2 variables → 4, 3 → 8, 4 → 16. Cells are ordered in Gray code (00, 01, 11, 10) so neighbours differ by one bit.
  • SOP: group 1s (minterms). POS: group 0s (maxterms).
  • Grouping rules: groups of 1, 2, 4, 8, 16 (powers of 2); rectangles only, no diagonals; make groups as large as possible; groups may overlap and wrap around edges; every 1 must be covered.
  • In a group, the variable that changes is eliminated; the constant ones remain.

Don't-care conditions

Input combinations that never occur; shown as "X" (or d). They can be treated as 0 or 1 — whichever makes bigger groups and a simpler result.

F(A,B,C) = Σm(0,1,3,5) + d(2,4) → A′ + B′

Combinational Circuits

  • Half adder — adds two single bits; outputs Sum = A ⊕ B, Carry = A · B. Made of 1 XOR + 1 AND gate.
  • Full adder — adds three bits (A, B, Carry-in); Sum = A ⊕ B ⊕ Cin, Cout = AB + Cin(A ⊕ B). Made of 2 half adders + 1 OR gate.
  • Half / full subtractor — Difference = A ⊕ B, Borrow = A′B (half).
  • Encoder — 2n input lines → n output lines (e.g. 8-to-3 octal-to-binary); built with OR gates. Priority encoder handles multiple inputs.
  • Decoder — n inputs → 2n output lines (e.g. 3-to-8); built with AND gates.
  • Multiplexer (MUX) — many inputs → one output, chosen by select lines (2n inputs need n select lines) — "data selector".
  • Demultiplexer (DEMUX) — one input → many outputs.
Analog → digital conversion is done by an ADC and digital → analog by a DAC — not by an encoder/decoder.

Sequential Circuits & Flip-Flops

  • Output depends on present input and past state (memory). Flip-flop = 1-bit memory element; register = group of flip-flops.
  • SR (Set-Reset) — S = R = 1 is not allowed (forbidden/invalid state, race condition). Used in counters, registers.
  • JK (Jack Kilby) — improvement over SR; J = K = 1 → toggle; no invalid state. Master-slave JK avoids race-around.
  • T (Toggle) — T = 0 no change, T = 1 toggle; output frequency is half the input → used in counters and frequency dividers, parity checkers.
  • D (Data / Delay) — output follows input on each clock pulse (Q = D); used to build registers & shift registers.

Computer Organization & CPU

  • Father of computer architecture: John von Neumann (stored-program concept — program and data stored in the same memory).
  • Parts of a computer: CPU, memory, input devices, output devices.
  • CPU (Central Processing Unit) = processor / microprocessor; "brain of the computer". Understands only machine language (binary).
  • CPU speed measured in Hertz — MHz, GHz. Also MIPS (Million Instructions Per Second), KIPS (Kilo IPS).
  • Parts of CPU: CU (Control Unit — controls input/output, decodes instructions), ALU (Arithmetic Logic Unit — executes arithmetic & logical operations; result stored in accumulator), MU (Memory unit — registers, fastest memory).
  • Machine (instruction) cycle: Fetch → Decode → Execute (→ Store).
  • System bus: address bus (unidirectional), data bus (bidirectional), control bus.

Memory Hierarchy

Fastest → slowest: Registers → Cache → Main memory (RAM) → Secondary storage (HDD/SSD) → Tertiary (tape). Speed and cost per bit decrease, capacity increases going down.

  • Primary / internal / main memory: RAM, ROM (semiconductor memory). Cache & registers are also considered primary.
  • Secondary / external memory: HDD, SSD, CD, DVD, Blu-ray, pen drive, memory card.

RAM

  • Random Access Memory — temporary, volatile, read + write. Founder (DRAM): Robert Heath Dennard (IBM, 1966).
  • SRAM (Static) — made of transistors/flip-flops; fastest; no refresh; used for cache memory; costly.
  • DRAM (Dynamic) — made of capacitors; slower; needs refreshing; used as main memory in PCs/mobiles.
  • DRAM types: SDRAM (Synchronous DRAM), DDR SDRAM (Double Data Rate) — DDR1, DDR2, DDR3, DDR4, DDR5.

ROM

  • Read Only Memory — non-volatile, permanent; stores BIOS / firmware (firmware = hardware + software); helps in booting.
  • PROM — Programmable ROM, written once, no editing (Wen Tsing Chow, 1956).
  • EPROM — Erasable PROM, erased by UV rays (Dov Frohman, 1971).
  • EEPROM — Electrically Erasable PROM, erased by electric signals (George Perlegos).
  • Flash memory — type of EEPROM: pen drive, memory card, SSD (invented by Fujio Masuoka, Toshiba).
  • Booting: loading the OS from secondary storage into RAM. Cold boot (power on) / warm boot (restart). BIOS → POST (Power-On Self-Test) → bootloader.

Cache Memory

  • 2nd fastest memory; volatile; small (KB – MB); located between CPU and RAM; stores frequently used instructions & data.
  • Data found in cache = hit; not found = miss. Performance measured by hit ratio = hits / (hits + misses).
  • Levels: L1 (inside core, fastest), L2, L3 (shared).
  • LRU (Least Recently Used) — common cache replacement policy: discards the least recently used item first when the cache is full.
  • Word transfer: CPU ↔ cache; block transfer: cache ↔ main memory.
  • Cache mapping: Direct, Associative (fully), Set-associative.

Registers

  • Fastest memory; inside CPU; collection of flip-flops. Holds 32/64 bits. CPU word size = register size.
  • Functions: fetch, decode, execute.

Virtual, Buffer & Flash Memory

  • Virtual memory — illusion of a larger RAM; uses secondary storage; swap in/swap out; implemented via paging/segmentation (page replacement).
  • Buffer — temporary storage in RAM to hold data before use (e.g. video buffering: first part downloaded then played).
  • Flash — pen drive (USB stick), memory stick, SD card, SSD.

SIMM vs DIMM

  • Magnetic tape — sequential access, used for backup.

Functions of OS

Process management, memory management, file management, device (I/O) management, security, job accounting, secondary storage management, networking, error detection, coordination between software and users.

Types of OS

Process & Process States

  • Program in execution = process. Represented by a PCB (Process Control Block): PID, state, program counter, registers, priority, memory info.

States: New → Ready → Running → Waiting (Blocked) → Terminated (plus Suspended-ready / Suspended-blocked).

  • New — process being created (program in hard disk).
  • Ready — loaded in RAM, waiting for CPU (ready queue, FIFO). Brought by long-term scheduler.
  • Running — executing on CPU (uniprocessor/multiprocessor). Chosen by short-term scheduler; the dispatcher gives CPU to it.
  • Waiting/Blocked — waiting for I/O or an event; also when a higher-priority process takes CPU or time quantum ends.
  • Terminated — finished; resources de-allocated.
  • Suspended — swapped out to secondary memory when RAM is full; done by medium-term scheduler (swap-in / swap-out).

Deadlock

A set of processes is blocked forever because each holds a resource and waits for a resource held by another (infinite waiting). System model: request → use → release.

Necessary conditions (Coffman) — all 4 must hold

  1. Mutual exclusion — at least one resource is non-shareable.
  2. Hold and wait — process holds a resource and waits for others.
  3. No preemption — resources can't be forcibly taken.
  4. Circular wait — P1 → P2 → P3 → P1 chain of waiting.

Handling

  • Prevention — break one of the 4 conditions. Avoidance — Banker's algorithm (Edsger Dijkstra): safety algorithm + resource-request algorithm; checks the system stays in a safe state, like a bank never lending money it can't recover. Detection & recovery — wait-for graph, kill/rollback processes. Ignore — Ostrich algorithm (Windows/Linux).
  • Starvation — a process waits indefinitely; livelock — processes keep changing state without progress.

Interrupts

  • Signal that temporarily halts the CPU's current activity to attend to something more urgent. Handled by an ISR (Interrupt Service Routine); state saved on stack. Time taken to respond = interrupt latency.
  • Hardware interrupts: maskable (can be disabled/ignored by CPU) and non-maskable (can't be ignored — power failure, highest priority).
  • Software interrupts: normal (caused by instructions) and exceptions (e.g. divide by zero).
  • 8085 hardware interrupts (5): TRAP (non-maskable, highest), RST 7.5, RST 6.5, RST 5.5, INTR (lowest; maskable). Software interrupts RST 0 – RST 7.

Memory Management

  • CPU generates a logical (virtual) address; main memory uses a physical address. Translation is done by the MMU (Memory Management Unit) under OS control.
  • Contiguous allocation — process stored in one continuous block. Problem: external fragmentation (total free space is enough but not contiguous).
    • Static (fixed) partitioning — memory pre-divided into fixed-size partitions; causes internal fragmentation (unused space inside a partition).
    • Dynamic (variable) partitioning — partitions created as per process size; no internal fragmentation.
  • Non-contiguous allocation — process spread across memory: paging and segmentation.
  • Compaction — collects all free memory into one large block to solve external fragmentation.

Placement algorithms

  • First fit — first hole large enough; fast; external fragmentation.
  • Next fit — like first fit but starts from where it last left off.
  • Best fit — smallest hole that fits; slow; leaves tiny unusable holes.
  • Worst fit — largest hole; leaves big remaining holes.

Paging & Segmentation

  • Paging: logical memory divided into fixed-size pages; physical memory into frames of the same size (page size = frame size). Page table maps pages to frames. Removes external fragmentation (may cause small internal fragmentation). Important for virtual memory.
  • Logical address = page number (p) + offset (d); physical address = frame number (f) + offset (d).
  • Page fault — CPU requests a page not present in RAM. Thrashing — CPU spends more time swapping pages than executing (too many page faults) → low CPU utilization.
  • TLB (Translation Look-aside Buffer) — small fast cache of page-table entries (TLB hit / miss); uses locality of reference.
  • Segmentation — memory divided into variable-size logical units (code, data, stack) — user's view. Segment table holds base (starting physical address) and limit (length). Suffers external fragmentation.
Logical address 13 bits, physical 12 bits, page size 1 KB (210) → offset 10 bits. Pages = 213−10 = 8; frames = 212−10 = 4.
Logical address 27 bits, physical 21 bits, page size 1 KB → pages 217 = 128 K; frames 211 = 2048.

Page Replacement Algorithms

Decide which page to swap out of RAM to make space, aiming to reduce page faults.

  1. FIFO — remove oldest page; suffers Belady's anomaly (more frames can cause more page faults — seen in FIFO).
  2. Optimal — replace the page not used for the longest time in future; fewest faults; not implementable in practice (benchmark).
  3. LRU — replace the least recently used page.

Process Synchronization & Semaphores

  • Critical section — code accessing shared resources. Race condition — output depends on order of execution.
  • Requirements: mutual exclusion, progress, bounded waiting.
  • Semaphore (Dijkstra) — integer variable/abstract data type used to control access to shared resources by multiple processes; synchronization primitive. Two atomic operations: wait() / P (decrements; blocks if ≤ 0) and signal() / V (increments, wakes a process).
  • Types: binary semaphore (mutex lock) — 0/1; counting semaphore — controls access to a resource with many instances.
  • Classic problems: bounded-buffer (producer–consumer), readers–writers, dining philosophers, sleeping barber.

  • Disk access time = seek time + rotational latency + transfer time.

Problem-Solving Cycle

  1. Analyse the problem — understand inputs, outputs and requirements.
  2. Develop an algorithm — step-by-step solution (flowchart / pseudocode).
  3. Coding — convert algorithm into a program.
  4. Testing & debugging — run with test data, find and fix errors.

Also called the steps: understand → plan → implement → test → maintain.

Algorithm

  • Finite sequence of well-defined steps to solve a problem.
  • Characteristics: input (zero or more), output (at least one), definiteness (each step clear), finiteness (ends after finite steps), effectiveness (each step basic and doable).
  • Representation: natural language, flowchart, pseudocode.
Algorithm: largest of two numbers

4. Stop

  • Informal, English-like description of an algorithm using programming-style structure; not tied to any language; can't be executed.
  • Common keywords: INPUT/READ, OUTPUT/PRINT, IF…THEN…ELSE, WHILE, FOR, COMPUTE, SET, INCREMENT.

Flow of Control

  • Sequence — statements executed one after another.
  • Selection (decision) — choose a path based on a condition: if, if-else, switch.
  • Iteration (repetition/loop) — repeat steps: for, while, do-while.

Any algorithm can be built from these three constructs (structured programming).

Verifying & Comparing Algorithms

  • Verification — dry run (trace by hand with sample inputs) to check the algorithm gives correct output.
  • Comparison — by time complexity (number of steps) and space complexity (memory). E.g. to check prime, testing divisors up to √n is faster than up to n−1.

Decomposition

  • Breaking a complex problem into smaller, simpler sub-problems that are solved separately and then combined.
  • Example: a railway reservation system → search trains, check seats, book ticket, payment, generate PNR.
  • Related computational-thinking ideas: pattern recognition, abstraction (focus on what matters), algorithm design.
  • In programming, decomposition is done using functions/modules (modular programming).

Array

  • Collection of similar elements in contiguous memory; random access by index; index starts at 0.
  • C: int arr[3] = {1,2,3};   Java: int[] arr = new int[5];, multi-dimensional int[][] a;

Stack

  • Linear structure following LIFO (Last In First Out) — like a pile of plates. Only one end (top) is open.
  • Operations: push (add on top), pop (remove top), peek/top (read top without removing), isEmpty, isFull.
  • Pop on empty stack → underflow; push on full stack → overflow.
  • Applications: function calls (call stack), recursion, undo/redo, expression evaluation & conversion, parenthesis matching, browser back button, stock span problem, DFS.
  • Disadvantage: no random access; too many items can cause stack overflow.

Queue

  • Linear ordered list following FIFO (First In First Out). Two ends: rear (insertion) and front (deletion).
  • Operations: enqueue (add), dequeue (remove), peek, isEmpty, isFull.
  • Implemented using arrays (static) or linked list (dynamic); also via stacks.
  • Applications: CPU scheduling, printer spooling, handling website traffic (request queue), routers (packet queue), traffic management, BFS, radix sort.

Types of queue

  1. Linear / simple queue — insert at rear, delete from front.
  2. Circular queue (ring buffer) — last position connected to first; avoids wasted space.
  3. Priority queue — served by priority; same priority → FIFO. Implemented with heap.
  4. Deque (double-ended) — insert/delete at both ends (palindrome checker). Types: input-restricted (insert at one end, delete at both) and output-restricted (delete at one end, insert at both).
Empty queue: front = rear = −1. One element: front = rear. Full (linear, size N): rear = N − 1. Circular full: (rear + 1) % N == front.

Linked List

  • Collection of nodes; each node = data + pointer (address) to next node. Elements stored anywhere in memory (not contiguous). Head points to first node; last node points to NULL.
  • Dynamic size; memory allocated at run time (array: compile time). Access is sequential (array: random). Easy insertion/deletion; no memory pre-allocation.
  • Types: Singly (one direction; hash tables), Doubly (prev + next; undo/redo, browser history), Circular (last node points to first; round-robin CPU scheduling), Circular doubly.
  • Sentinel node — dummy node that holds no data, simplifies boundary cases.

Trees

Non-linear hierarchical structure with no closed loops (cycles).

Terminology

  • Root — top node. Parent / child. Siblings — same parent. Leaf / external / terminal node — no child. Internal node — at least one child. Edge — link; a tree with n nodes has n − 1 edges.
  • Degree of node = number of children (leaf = 0). Degree of tree = max degree.
  • Depth/level of node = edges from root (root depth = 0). Height = edges on longest path from node to a leaf.

Types

  • General tree — any number of children.
  • Binary tree — at most 2 children (0, 1, 2).
    • Full / proper / strict — every node has 0 or 2 children (extended binary tree).
    • Perfect — all internal nodes have 2 children, all leaves at same level.
    • Complete — all levels filled except possibly last, filled left to right.
    • Degenerate / skewed — each node has one child (left-skewed, right-skewed).
    • Balanced — height difference of left and right subtrees ≤ 1.
  • Binary Search Tree (BST) — left child < parent < right child. Inorder traversal gives sorted order.
  • AVL tree — Adelson-Velsky & Landis (1962); self-balancing BST; balance factor −1, 0, +1; rotations LL, RR, LR, RL.
  • Red-Black tree — Rudolf Bayer (1972); self-balancing BST. Rules: root is black; every node red or black; red node can't have red child; every path has same number of black nodes.
  • B-tree — Bayer & McCreight (1970–72); self-balanced m-way search tree; node has multiple keys and more than two children; used in databases & file systems. B+ tree stores data only in leaves.
Max nodes at level l = 2l. Max nodes in binary tree of height h = 2h+1 − 1 (levels 0–5 → 63). Min height with n nodes = ⌈log2(n+1)⌉ − 1. In a full binary tree, leaves = internal nodes + 1.

Tree Traversal

  • BFS / level-order — level by level; uses queue.
  • DFS — uses stack: Preorder (Root, Left, Right), Inorder (Left, Root, Right), Postorder (Left, Right, Root).

Binary Heap

  • Complete binary tree. Max-heap: parent ≥ children (root = maximum). Min-heap: parent ≤ children (root = minimum).
  • Used in heap sort and priority queues. Insert/delete O(log n); get-min/max O(1).

Graphs

  • Non-linear structure of vertices (nodes) and edges; can contain cycles. Used to represent networks.
  • Applications: Google Maps (shortest path), Google search (PageRank), WWW, social networks.
  • Types: directed, undirected, weighted, unweighted, cyclic, acyclic (DAG), connected, disconnected, complete, bipartite.
  • Bipartite — nodes divided into two sets such that no edge joins nodes of the same set (students ↔ courses).
  • Complete graph — every pair connected: edges = n(n−1)/2.
  • Degree of a node = number of edges connected. Sum of degrees = 2 × edges. Size of graph = number of edges.
  • Negative cycle — loop whose total edge weight is negative.

Representation

  • Adjacency matrix — V×V matrix, 1 if edge exists; O(V²) space.
  • Adjacency list — each vertex keeps list of neighbours; O(V+E) space.

Graph traversal

  • BFS uses a queue (FIFO) — better when target is close to source; finds shortest path in unweighted graphs.
  • DFS uses a stack / recursion — better when target is far from source.
  • Both O(V + E).

Minimum Spanning Tree (MST)

A spanning tree connects all vertices without cycles using V−1 edges; MST has minimum total edge weight.

  • Kruskal's — greedy; sort edges by weight and add the smallest that doesn't form a cycle; uses Union-Find (disjoint set). O(E log E). Good for sparse graphs.
  • Prim's — greedy; start from any vertex and add the minimum-weight edge to a new vertex; uses priority queue. O(V²) with matrix, O(E log V) with heap. Good for dense graphs.
  • Used in LAN connections, TV networks, roads and rail tracks, travelling-salesman approximations.

Hashing

  • Converts data (key) into a fixed short value (hash) using a hash function; maps keys to values; goal: O(1) average search.
  • Examples: password storage, transaction protection, blockchain verification, integrity checks, unique IDs, digital signatures, OTPs.
  • Collision — two different keys produce the same hash.
  • Perfect hashing — guarantees no collisions.

Collision resolution

  2. Open addressing (closed hashing) — all elements stored in the table itself:
    • Linear probing — check next slot sequentially.
    • Quadratic probing — add 1², 2², 3²…
    • Double hashing — second hash function gives step size.

Bubble, selection & insertion sort

def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]

def selection_sort(a):
    for i in range(len(a)):
        m = i
        for j in range(i + 1, len(a)):
            if a[j] < a[m]:
                m = j
        a[i], a[m] = a[m], a[i]

def insertion_sort(a):
    for i in range(1, len(a)):
        key, j = a[i], i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key

Ch 6: Pointers

Call by value vs call by reference

Statistical Techniques

  • Mean = sum of values ÷ number of values.
  • Median = middle value after sorting (even count → average of two middle values).
  • Mode = most frequent value.
  • Range = maximum − minimum.
  • Variance (σ²) = average of squared differences from the mean = Σ(x − x̄)² ÷ n.
  • Standard deviation (σ) = √variance — how spread out the values are. Small SD → values close to mean.
Data: 2, 4, 4, 4, 5, 5, 7, 9 (n = 8)
Mean = 40 ÷ 8 = 5 · Median = (4 + 5) ÷ 2 = 4.5 · Mode = 4 · Range = 9 − 2 = 7
Squared deviations: 9, 1, 1, 1, 0, 0, 4, 16 → sum 32 → Variance = 32 ÷ 8 = 4 → SD = 2
(Sample variance uses n − 1: 32 ÷ 7 ≈ 4.57.)

Mean, median, mode = measures of central tendency; range, variance, SD = measures of dispersion (variability).

Basic Concepts of Database

Hierarchy: Bit → Byte → Field → Record → Table/File → Database

  • Bit = smallest unit (0/1). Byte/character = 8 bits. Field = group of bytes. Record = group of fields. File/Table = group of records. Database = group of files/tables.

  • DBMS (Database Management System): software that stores, modifies and retrieves data. RDBMS: DBMS that stores data in related tables.

Less data redundancy & inconsistency, data integrity & security, stores any type of data, ACID properties, easy access, SQL support, data sharing, decision making, backup & recovery, multi-user concurrent access.

Database Architecture (Tiers)

  1. 1-tier (single tier) — database directly available to the user on the same machine (local database system); any change is done directly on the database. Used for local application development.
  2. 2-tier — client–server. Client application talks to the server using APIs like ODBC (Open Database Connectivity, by Microsoft, SQL-based) and JDBC (Java Database Connectivity, by Sun Microsystems).
  3. 3-tier — client (presentation) ↔ application server (business logic) ↔ database server. Used for large web applications.

Three-Schema Architecture (ANSI/SPARC)

  • Proposed by ANSI/SPARC (American National Standards Institute / Standards Planning and Requirements Committee).
  • External level (view level) — closest to the user; shows only relevant data; many views for different users.
  • Conceptual level (logical level) — describes structure of the whole database: entities, relationships, constraints, security. Designed by DBA/programmers. Doesn't care how data is stored.
  • Internal level (physical level) — lowest level; how data is actually stored on disk (files, blocks, indexes, compression, encryption).
  • Data independence: logical (change conceptual schema without changing external) and physical (change internal without changing conceptual).

Schema vs Instance

  • Schema: logical design / blueprint / skeleton of the database (table names, fields, data types, relationships). Defined using DDL; rarely changes. Types: physical schema (storage in files & indices), logical schema (tables, views, integrity constraints — ER model used here), view schema (how end users interact).
  • Instance: snapshot of the data in the database at a given moment; changes with insert/update/delete.

ACID Properties (Transactions)

  • Atomicity — all or nothing: a transaction either completes fully or not at all.

Database Keys

  1. Super key — set of one or more attributes that uniquely identifies rows (e.g. {Emp_id}, {Emp_id, Emp_name}).
  2. Candidate key — minimal super key; one of them becomes primary key.
  3. Primary key — chosen candidate key; unique, NOT NULL; only one per table.
  4. Alternate key — candidate keys not chosen as primary (also "secondary keys").
  5. Composite / compound key — key made of two or more attributes when no single attribute is unique (ATM card + PIN; username + OTP).
  6. Foreign key — column that refers to the primary key of another table; links tables; maintains referential integrity; can be NULL and duplicate.
  7. Surrogate key — system-generated synthetic key (auto-increment ID), used e.g. when merging data of two companies.

Normalization

Process of removing redundancy and unwanted anomalies by decomposing tables. Introduced by E. F. Codd.

Anomalies (why normalize)

  • Insertion anomaly — can't insert data without other data (e.g. can't add a new branch until a student joins it).
  • Deletion anomaly — deleting a row loses other useful data (deleting the last student of a branch deletes branch info).
  • Update anomaly — same data stored in many rows must be updated everywhere, else inconsistency.

Views, Cursors, Locks, Triggers

Introduction & History

  • Computer networking: interconnected computing devices that exchange data and share resources with each other.
  • First network: ARPANET (Advanced Research Projects Agency Network) — USA, Department of Defense, 1969.
  • TCP/IP was developed for ARPANET by Vint Cerf & Bob Kahn (called "Fathers of the Internet").
  • Before TCP/IP, ARPANET used NCP (Network Control Protocol).
  • First e-mail was sent over ARPANET in 1971 by Ray Tomlinson (he also introduced the @ sign in addresses).
  • 1 January 1983 — ARPANET switched to TCP/IP: the "official birthday of the Internet".
  • First public internet service in India: VSNL (Videsh Sanchar Nigam Limited) on 15 August 1995.
  • WWW invented by Tim Berners-Lee (1989, CERN).

Evolution of Networking

  • ARPANET (1969) — first network, connected 4 university/research computers (UCLA, Stanford, UCSB, Utah).
  • NSFNET (1986) — National Science Foundation Network; connected universities and research centres at high speed; replaced ARPANET as the backbone (ARPANET shut down in 1990).
  • Internet — global network of networks formed by interconnecting ARPANET, NSFNET and private networks; opened to commercial use in the early 1990s.

Networking Models: OSI & TCP/IP

A networking model is a set of guidelines and standards that define how data is transmitted and received over a network.

  • TCP/IP model (1970s–1982) — adopted as the standard protocol suite of ARPANET in 1983. Practical model actually used on the Internet.
  • OSI model (Open Systems Interconnection) — published by ISO (International Organization for Standardization) in 1984. 7 layers. It is a reference/conceptual model, not practically implemented as such. Purpose: describe how data travels in a network.

Trick (top→down): All People Seem To Need Data Processing. Bottom→up: Please Do Not Throw Sausage Pizza Away. Layers 1–3 = hardware/"media" layers; 5–7 = software/"host" layers; Transport = "heart of OSI". PDU = Protocol Data Unit.

Layer details

  • Physical layer: physical connection, topology, transmission mode (simplex/half/full duplex), bit synchronization, bit-rate control.
  • Data Link layer: MAC (Ethernet) addressing, error-free transfer of frames, flow control, error control. Node-to-node delivery. Two sub-layers: LLC (Logical Link Control — error/flow control) and MAC (Media Access Control — 48-bit physical address on NIC).
  • Network layer: routing & forwarding of packets, internetworking, logical (IP) addressing, source-to-destination (host-to-host) delivery.
  • Transport layer: end-to-end / process-to-process delivery using port numbers, acknowledgement, segmentation. TCP = connection-oriented, UDP = connectionless. TLS/SSL also operate around here.
  • Session layer: session establishment & management, synchronization (checkpoints), dialog & token management.
  • Presentation layer: also called translation/syntax layer — translation, encryption, compression.
  • Application layer: also called desktop layer; closest to the end user. Network virtual terminal, file transfer (FTAM), mail services, directory services.
A firewall can work at layers 3, 4 and 7 of OSI.

Subnetting

A subnet is a network inside a network. Subnetting divides a large network into smaller ones — makes networks efficient and improves security.

  • Number of hosts = 2h − 2 (h = host bits; network ID and broadcast ID excluded).
  • Number of subnets = 2n (n = borrowed bits).
Q. How many hosts with mask 255.255.255.128? → last octet 10000000 → 7 host bits → 27 − 2 = 126.
Q. Mask 255.255.255.252? → 2 host bits → 22 − 2 = 2 hosts.
Q. Host part of 192.168.10.51 with default mask (class C)? → network 192.168.10, host 51.

Internet & IoT Basics

  • Internet = network of networks; a superset of the World Wide Web. Father of Internet: Vint Cerf. Owner of Internet: none.
  • IoT = a network of interrelated devices ("things") with sensors, software and connectivity that collect and exchange data. A "thing" can be a person with a heart-monitor implant, a farm animal with a biochip transponder, or a car with built-in sensors.
  • Term IoT coined by Kevin Ashton in 1999.
  • First IoT device: a toaster connected to the internet by John Romkey (1990). (Earlier, a Coca-Cola vending machine at Carnegie Mellon was networked in 1982.)

Types of IoT

  1. Consumer IoT — home appliances, voice assistants, smart lights.
  2. Commercial IoT — healthcare, transport, smart pacemakers, monitoring systems.
  3. Military IoT (IoMT) — surveillance robots, human-wearable biometrics.
  4. Industrial IoT (IIoT) — manufacturing & energy, digital control systems, smart agriculture, industrial big data.
  5. Infrastructure IoT — smart cities, infrastructure sensors, management systems.

Components of IoT

  1. Things / devices — sensors & actuators collect data and give it to the gateway.
  2. Gateway — pre-processing of data, security.
  3. Cloud — data uploaded to servers.
  4. Analytics — algorithms / machine learning applied.
  5. User interface — monitor/control the data.
  • Sensor — physical device that monitors and collects data from the environment (temperature, humidity, pressure, camera/optical sensors).
  • Actuator — converts energy/signal into motion (action).
  • Transducer — converts energy from one form to another (sensors and actuators are both transducers). Example: microphone.

IoT Gateway

Hardware device or software program that establishes communication between sensors and the cloud.

  • Bluetooth — named after King Harald "Bluetooth"; IEEE 802.15.1; range ~10 m (30 ft); 2.4 GHz. BLE (Bluetooth Low Energy / Bluetooth 4.0 "Smart") — developed by Nokia (Wibree, 2006).

  • ZigBee (IEEE 802.15.4) — low-cost, low-power personal area network; created by ZigBee Alliance; used by smart bulbs, plugs, sensors.

Low-power wide-area networks (LPWAN)

  • 4G LTE IoT — Long Term Evolution; speed ~20–30 Mbps (practical).
  • 5G IoT — up to 20 Gbps peak; Qualcomm played a major role.
  • Cat-0 / Cat-1 — LTE categories with lower throughput and long battery life.
  • LoRaWAN — Long Range WAN; used for monitoring energy in buildings, smart lighting.
  • NB-IoT (Narrowband IoT) and LTE-M (Cat-M1).
  • Sigfox — French global network operator (2010); cheap, reliable, low-power.

  • DDS (Data Distribution Service) — interoperable middleware protocol by OMG (Object Management Group); real-time data.
  • AMQP (Advanced Message Queuing Protocol) — by JPMorgan Chase; guaranteed message delivery; scalability.
  • HTTP — also used.

Network Security Threats

7 stages: Planning → Requirement Analysis → Design → Development (coding) → Testing → Deployment → Maintenance.

SDLC Models

  1. Waterfall — first SDLC model; linear sequential; next phase starts only when previous is complete; by Winston W. Royce (1970). Good when requirements are fixed.
  2. V-shaped — Verification & Validation model; testing at each step. Left side = verification (QA team, focus on process); right side = validation (testers, focus on product).
  3. Prototype — dummy prototype built before actual software; customer feedback; refined prototype; good when requirements are unclear.
  4. Spiral — iterative (loops) + prototype; by Barry Boehm (1986); risk-driven. 4 phases: planning, risk analysis, engineering, evaluation. Best for large, risky projects.
  5. Iterative & incremental (RUP) — product divided into small chunks. Phases: inception, elaboration, construction, transition.
  6. Big Bang — no defined process, little planning; small projects; no testing team.
  7. Agile — iterative + incremental; continuous collaboration and improvement; work broken into short phases called sprints (1–4 weeks). Agile Manifesto 2001.
  8. RAD (Rapid Application Development) — modification of incremental model; prototyping; less planning, more development; high speed. Phases: business modelling → data modelling → process modelling → application generation → testing & turnover.
  9. Scrum — Agile framework; focuses on teamwork for timely delivery. Roles: Product Owner, Scrum Master, Development Team. Daily stand-up, sprint review, retrospective.
  10. Kanban — Japanese for "card you can see"; visual task board to manage workflow; Just-in-Time; reduces time to complete tasks.
  11. COCOMO (Constructive Cost Model) — regression cost-estimation model based on LOC (lines of code); by Barry Boehm, 1981. Project types: organic, semi-detached, embedded.

CASE Tools

  • Computer-Aided Software Engineering tools for high quality, defect-free software. Central component: repository (stores all information).
  • Upper CASE — planning, analysis, design. Lower CASE — implementation, testing, maintenance. Integrated CASE — all stages.

Quality, Cohesion & Coupling

  • SQA (Software Quality Assurance) — process running parallel to development to assure quality. Focus: portability, usability, reusability, correctness, maintainability, error control.
  • Cohesion — measure of how strongly elements within a module are related. High cohesion is good.
  • Coupling — degree of interdependence between modules. Low coupling is good (changes in one module have little impact on others).
  • Goal of software engineering: meet user requirements within budget, schedule and time constraints.
  • Requirements: functional, non-functional (performance, security), domain, system.
  • ISO 9000 — quality assurance standards. SEI-CMM (Software Engineering Institute — Capability Maturity Model) — benchmark of an organization's software process maturity; 5 levels:
  1. Initial (chaotic, ad hoc)
  2. Repeatable (size & cost — COCOMO)
  3. Defined (documentation)
  4. Managed (metrics — product & process)
  5. Optimizing (process improvement)

Software Maintenance (4 types)

  1. Corrective — fixing errors & bugs.
  2. Adaptive — modifying software to adapt to environment changes (new OS/hardware).
  3. Perfective — improving functionality, performance, reliability; restructuring.
  4. Preventive — increasing future maintainability, preventing problems (taking backups, refactoring).

Software Testing

  1. Alpha testing — at developer's site by internal team in a virtual user environment; at end of development, before beta.
  2. Beta testing — by real customers/users in the real environment before release.
  3. Acceptance testing (UAT) — client verifies whether the system meets business requirements.
  4. Ad-hoc testing — informal, no plan/documentation; anyone in the project can do it.
  5. Accessibility testing — checks software is usable by disabled people (font size, contrast, screen readers).
  6. Back-end (database) testing — tables, schema, stored procedures; GUI not involved.
  7. Browser compatibility — web app works on different browsers/OS.
  8. Backward compatibility — new version works with files/data of older versions.
  9. Black-box testing — internal code not visible to tester; based on requirements; behavioural testing.
  10. White-box testing — code visible to tester; also called glass-box, clear-box, open-box, transparent testing.
  11. Grey-box — partial knowledge of internals.
  12. Unit testing — individual modules; done by programmers.
  13. Integration testing — combined modules tested as a group (top-down, bottom-up, big-bang); checks interfaces.
  14. System testing — complete integrated system.
  15. Smoke testing (build verification) — new build is stable enough for further testing.
  16. Sanity testing — quick check of specific functions after small changes (login, menus).
  17. Regression testing — re-testing after changes to ensure old features still work.
  18. Interface / GUI testing — GUI meets requirements; look and feel.
  19. Boundary value testing — tests at upper and lower boundaries of input ranges.
  20. Gorilla testing — one module tested repeatedly (hundreds of times) — "frustrating testing"; checks robustness.
  21. Performance testing — load (expected load), stress (beyond limits), volume, scalability.
  22. Monkey testing — random inputs without test cases. Exploratory testing — learning + testing together.

Verification vs Validation

Verification: "Are we building the product right?" — reviews, walkthroughs, inspections (static). Validation: "Are we building the right product?" — actual testing (dynamic).

Other key terms

  • SRS — Software Requirement Specification document.
  • Function Point analysis — size measure based on functionality (Allan Albrecht, IBM).
  • Cyclomatic complexity (McCabe) = E − N + 2P (edges, nodes, connected components) — number of independent paths.
  • DFD (Data Flow Diagram) levels 0, 1, 2; UML diagrams (use-case, class, sequence, activity).
  • Error → fault/defect/bug → failure.

Theory of Computation

Introduction

  • Branch of theoretical computer science that studies how problems can be solved using algorithms / abstract machines.
  • 3 theories: Computability theory (what can and can't be computed), Complexity theory (what makes problems computationally hard or easy), Automata theory (abstract machines and the problems they solve).
  • Concepts: finite automata, regular expressions, context-free grammars, Turing machines, decidability, halting problem, pumping lemma.
  • Applications: cryptography, algorithm analysis, quantum computation, logic, compiler design, string/pattern matching, AI.
  • Alan Turing — father of theoretical computer science & AI; invented the Turing machine (1936). His teacher Alonzo Church developed lambda calculus (λ-calculus).
  • Church–Turing thesis: anything that can be computed by a step-by-step procedure can be computed by a Turing machine.

Automata Basics

  • Automaton = abstract machine. Symbol = character. Alphabet (Σ) = finite set of symbols. String/word = finite sequence of symbols. Language = set of strings.
  • Machines (weakest → strongest): Finite Automata → Pushdown Automata → Linear Bounded Automata → Turing Machine.

Chomsky Hierarchy

Finite Automata (DFA & NFA)

  • Concept by Warren McCulloch & Walter Pitts (1943, neurophysiologists studying the brain). Recognises regular languages (Type 3) — e.g. phone numbers, patterns. Used in text processing, compilers (lexical analysis), network protocols.
  • Formally a 5-tuple (Q, Σ, δ, q0, F).

DFA and NFA have equal power. A machine without output = acceptor.

Moore & Mealy Machines

  • Finite automata with output (transducers); 6-tuples (Q, Σ, Δ, δ, λ, q0) — no final states.
  • Moore machine — output depends only on the present state.
  • Mealy machine — output depends on the present state and current input. Generally needs fewer states.

Pushdown Automata (PDA)

  • Finite automaton + stack (extra memory, LIFO). Recognises context-free languages (Type 2), e.g. aⁿbⁿ, balanced brackets. Used in parsers.
  • Components: input tape, finite control, stack (push/pop).
  • DPDA is less powerful than NPDA.

Linear Bounded Automata (LBA)

  • Turing machine with tape limited to the input size (between left and right end markers). Recognises context-sensitive languages (Type 1).
  • Introduced by John Myhill (1960); Peter Landweber and S.-Y. Kuroda showed equivalence with CSL.
  • More powerful than PDA, less powerful than TM.

Turing Machine

  • Invented by Alan Turing in 1936 — mathematical model of a general-purpose computer; most powerful model; accepts recursively enumerable languages (Type 0).
  • Has an infinite tape divided into cells, a read/write head moving left/right, finite control (states). Reads one symbol at a time; can modify its own input ("writing machine").
  • 7-tuple (Q, Σ, Γ, δ, q0, B, F). Accept state = successful; reject state = unsuccessful.
  • Halting problem — whether a TM will halt on an input or run forever — is undecidable (proved by Turing).
  • Variations (all equal in power): multi-track, two-way infinite tape, multi-tape, multi-head, multi-dimensional, non-deterministic TM, universal TM.

Regular Expressions & Closure Properties

  • Kleene star (Σ*) — zero or more repetitions; includes null (ε). E.g. meow* → meo, meow, meoww…
  • Kleene plus (Σ⁺) — one or more repetitions; excludes null.
  • Closure property: applying an operation to languages of a class yields a language of the same class.

Myhill–Nerode Theorem & Pumping Lemma

  • Myhill–Nerode theorem (1958): necessary and sufficient condition for a language to be regular; used to prove regularity and to minimise DFA states.
  • Pumping lemma: "pumping" = generating many strings by repeating a part; "lemma" = intermediate theorem. Two versions — for regular languages and for context-free languages. Used to prove a language is not regular / not context-free (e.g. aⁿbⁿ is not regular).

Compiler Phases (TOC application)

  1. Lexical analysis (scanner — tokens; uses finite automata)
  2. Syntax analysis (parser — parse tree; uses CFG/PDA)
  3. Semantic analysis (type checking)
  4. Intermediate code generation (e.g. three-address code)
  5. Code optimization
  6. Code generation (target machine code)

Symbol table and error handler work with all phases. Front end = phases 1–4; back end = 5–6.
